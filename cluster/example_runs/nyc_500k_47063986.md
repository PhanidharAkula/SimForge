> **Why is the progress in `.err`?** This run predates the logging-stream
> change. Until then, library `basicConfig` calls (in `pipeline/...`) fired
> first during transitive imports and defaulted the root logger to stderr.
> The four entry points now pass `stream=sys.stdout, force=True`, so on
> subsequent runs the equivalent `INFO`/`WARNING`/`ERROR` lines land in the
> SLURM **`.out`** file; `.err` is reserved for uncaught Python tracebacks
> and external-tool stderr (SUMO, MATSim, …).

> **Why osmnx 1.9.4?** This run also predates the v2.x migration committed in
> `f31604f`. The `FutureWarning` shown in Step 1 is exactly what triggered
> the migration; runs against `osmnx>=2.0,<3` no longer emit it. Pipeline
> outputs are byte-identical between the two paths — the warning is purely
> a kwargs-rename heads-up.

This step dominates wall-time. The gravity sampler is a single-threaded NumPy
loop that, for each of the 500 000 sampled trips, runs a vectorized haversine
+ gravity weight over all 423 268 SCC destination nodes — roughly
2.1 × 10¹¹ float ops on a single core. `--cpus-per-task=8` does not help this
step; the only levers are `num_trips`, the network size (radius), or
rewriting the inner loop with multiprocessing/numba.
